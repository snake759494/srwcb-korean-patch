## #1 — 작전목적 창 `E7 02`

### 무엇이 일어났나

8화에서 증원이 오면 승리 조건이 "갼(마 쿠베) 파괴"로 바뀌고 작전목적 창이 갱신됩니다.
이 창은 풀 안의 블록을 읽습니다.

    04 00 | L 00 | 승리조건 … FF FF | 패배조건 … FF FF

`E7 02 <변위>` 핸들러는 블록에서 두 문자열을 찾아 **스택의 128바이트 버퍼에 0xFF 까지
길이 검사 없이** 복사합니다. 두 가지가 어긋나 있었습니다.

1. **`E7 02` 변위가 옛 값이었습니다.** 앞 블록의 승리조건이 번역으로 2바이트 늘어 뒤 블록이
   밀렸는데, `E7 02` 는 대사 포인터 목록에 없어 재조준되지 않았습니다. 창은 블록 2바이트 앞을
   읽어 쓰레기 오프셋(`0xFFA6`)을 얻었고, 시나리오 밖의 **배경음악 시퀀스 데이터를 문자열로 삼아
   10,855바이트**를 스택에 복사했습니다.
2. 그 복사가 메인 루프의 저장된 복귀 주소를 `0x47003544` 로 덮었습니다. 아무 일 없이 대사가
   이어지다가 **8화 장면이 끝나 메인 루프가 반환하는 순간** 쓰레기 주소로 뛰어 멈췄습니다.

제보해 주신 추적 빌드 세이브 두 장(대사 중 / 멈춤)으로 확정했습니다. 멈춤 세이브의 커널
예외 문맥(EPC `0x47003544`, 명령어 페치 버스 오류)과 덮인 스택 바이트가 음악 파일과 정확히
일치했습니다. 옛 저장소 #32 도 같은 증상이었는데 그때는 풀 이벤트 참조 문제로 잘못 짚었습니다.

### 블록 안 L 도 틀려 있었다

`L` 은 창폭이 아니라 **패배조건 문자열의 위치**입니다(`blk + L + 2`). 그동안 게이트가 "원문과
같은 값"을 요구해서, 승리조건 길이가 바뀐 블록의 L 이 옛 값으로 남았습니다. 그 블록들은 작전목적
창의 **패배조건이 빈 칸이거나 글자 중간부터** 나왔습니다.

| | 변위 스테일 | L 불일치 |
|---|---|---|
| 제2차 | 1 → 0 | 14 → 0 |
| 제3차 | 0 | 0 |
| EX | 0 | 0 |

### 고친 방법

- `E7 02` 를 포인터 형식으로 등록했습니다(`tools/analyze_sce_relocation.py`).
- `tools/objective_windows.py` 가 이미지 조립 마지막에 `E7 02` 변위와 블록 L 을 다시 씁니다.
  블록은 모양으로 찾지 않고, 원문 `E7 02` 가 실제로 가리키는 곳과 작전목적 머리글로 정의합니다.
  모양으로 찾으면 EX 1화 스크립트 속 우연한 `FF 04 00 ?? 00` 을 블록으로 오인해 망가뜨립니다.

## #4 — EX 장 선택 화면 칸 경계

장 선택 줄은 `[장 이름] │ [난이도]` 두 칸이고, 모든 줄에서 둘째 칸 첫 글자가 같은 위치(원문 8)여야
칸 구분선이 글자에 걸리지 않습니다. 셋째 줄 `슈우편 │ 레벨 어려움` 은 폭 18 로 원문 17 을 넘어,
폭 맞춤 단계가 공백을 깎았습니다. 그 결과 이름 칸이 4(원문 5)로 줄고 난이도 칸이 2 만큼 당겨졌습니다.
트레이닝 모드도 같은 상태였습니다.

세 줄 모두 레이블 "레벨"을 빼고 난이도만 적었습니다.

    마사키 │ 쉬움        류네편 │ 보통        슈우편 │ 어려움

ISS 질문 창에 가려지는 부분 줄은 원문처럼 첫 글자만 둡니다. EX 와 트레이닝 모드 모두 적용했습니다.
