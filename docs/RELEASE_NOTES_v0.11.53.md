# v0.11.53 — 프리징 긴급 수정: 이벤트 참조 5곳이 스테일이었습니다

**#39(제2차 브라이트 대사 후·전함 출격 후 정지)** 의 원인을 찾아 고쳤습니다.
v0.11.45 에서 들어간 안전장치가 **이벤트 스크립트 참조 다섯 곳을 재조준 대상에서
빼 버려서**, 그 자리를 밟는 순간 스크립트가 남의 레코드 한가운데로 뛰었습니다.

| 게임 | 자리 |
|---|---|
| 제2차 | `sc4` |
| EX | `sc8` · **`sc23`** · `sc52` · `sc55` |

`sc23` 은 **23화 듀라크실** 장면입니다 — v0.11.40 에서 고쳤던 곳이 되돌아가 있었습니다.

---

## 무엇이 문제였나

번역으로 텍스트가 길어지면 레코드가 뒤로 밀립니다. 그래서 이벤트 스크립트 안의
`B1/B3/B4 <변위16>` 참조를 **원래 가리키던 레코드 서수**로 다시 조준합니다.

문제는 **피연산자의 낮은 바이트가 레코드 종단자 `0xFF` 와 겹치는 자리**입니다.

```
레트일 sc4 rec0 꼬리   ... 58 01 b3 | ff 05 ...
                              ^^^^^   ^^^^^
                              옵코드   변위(0x05FF) — 낮은 바이트가 곧 0xFF
```

우리 도구는 레코드를 `0xFF` 로 끊으므로 이 자리를 재조준하면 경계가 움직입니다.
v0.11.45 는 그 흔들림을 피하려고 **이런 자리를 통째로 건너뛰게** 했습니다.

```python
if host is None or operand + 1 >= host.end - 1:   # <- 진짜 포인터까지 함께 버린다
    continue
```

건너뛴 자리는 **레트일 변위 그대로** 남습니다. 제2차 `sc4` 는 614바이트, EX 는
네 곳이 각각 수백 바이트씩 어긋난 곳을 가리켰습니다.

**게이트도 같이 눈이 멀었습니다.** v0.11.45 가 추가한 검사는 같은 함수를 다시
호출하는 방식이라, 그 함수가 건너뛴 자리는 검사에도 안 보였습니다. 그래서
"이벤트 포인터 잔류 0" 으로 보고되면서 다섯 곳이 스테일인 채 배포됐습니다.

## 어떻게 고쳤나

1. **가드를 원칙에 맞게 좁혔습니다** — 피연산자가 레코드 **밖에서 시작**할 때만
   포인터가 아니라고 봅니다(`operand >= host.end`).
2. **중복 재조준을 걷어냈습니다** — 제2차 빌드 안에서 한 번만 적용하던 것을 뺐습니다.
   이미지 조립의 `step_sce` 가 *고칠 게 없을 때까지 되풀이* 하며 처리합니다.
   한 번만 적용하면 새 변위 때문에 경계가 움직였을 때 서수가 어긋나 영영 안 맞습니다.
3. **경계 안정화 루프의 종료 조건을 되돌렸습니다** — v0.11.45 가 조건을 더해
   400회 안에 수렴하지 못하고 있었습니다(늘림 403개 → **26개**).

## 게이트 — 재조준기와 독립적으로 봅니다

`audit/verify_pool_event_refs.py` 를 넣었습니다. 재조준기를 다시 호출하지 않고
**레트일과 배포본을 직접 대조**합니다.

> 레트일에서 레코드 시작을 겨누던 참조는, 배포본에서도 **같은 서수의 레코드 시작**을 겨눠야 한다.

| | 스테일 |
|---|---|
| v0.11.44 (증상 없던 판) | 0 |
| **v0.11.45 ~ v0.11.52** | **5** |
| v0.11.53 | 0 |

증상이 없던 판에서 0, 증상이 난 판에서 5 — 이 게이트가 이 버그를 정확히 집습니다.
